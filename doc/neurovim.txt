1. INTRODUCTION                                               *neurovim-intro*

NeuroVim is a spy thriller you play with Vim motions. Every mission is a
corrupted transmission from CIPHER: you repair the text in an ordinary Neovim
buffer, with whatever Vim you know, and |:NeuroVim| check compares it with the
original. Solved missions earn XP, levels unlock the next missions, and the
fewer keys you need, the better your tier.

There are 40 story missions in ten chapters, each with a briefing, and 14
KATAs: short drills without a briefing. The plugin draws only what Neovim
lacks — a mission list, an objective above the text, a winbar — and leaves
colours, keys and everything else to your own configuration.

==============================================================================
2. REQUIREMENTS                                        *neurovim-requirements*

- Neovim 0.10 or newer.
- Nothing else: no Node, no helper process, no other plugin.

==============================================================================
3. INSTALL                                                  *neurovim-install*

With lazy.nvim: >lua
  { "johannes-kaindl/neurovim.nvim" }
<
From a local checkout: >lua
  { dir = "~/path/to/neurovim.nvim" }
<
The plugin defines |:NeuroVim| and four |<Plug>| mappings when it loads,
nothing else. Calling setup() is not needed.

                                                            *neurovim-options*
setup() takes one option; each call starts from the defaults. With lazy.nvim:
>lua
  { "johannes-kaindl/neurovim.nvim", opts = { isolate = false } }
<
Without a plugin manager: >lua
  require('neurovim').setup({ isolate = false })
<
                                                            *neurovim-isolate*
isolate     boolean, default true. A mission buffer runs in plain Neovim, as
            `nvim --clean` would run it, so that the objective, par and the
            key count mean what they say. In the mission buffer only:

            - Keys in Normal, Visual and Operator-pending mode do what Vim
              does: every printable key, <C-a> <C-b> <C-d> <C-e> <C-f> <C-o>
              <C-r> <C-u> <C-v> <C-x> <C-y>, <CR>, <BS> and the arrow keys,
              and every mapping of yours that starts with one of them.
              Neovim's own default mappings stay (|default-mappings|), and
              so does matchit's %.
            - Yours stay: mappings under <Leader> and <LocalLeader>, function
              keys, window keys such as <C-w> and <C-h>, Insert mode.
            - Options that change what a key does to the text take Neovim's
              default: 'autoindent' 'cindent' 'expandtab' 'formatexpr'
              'formatoptions' 'indentexpr' 'iskeyword' 'lisp' 'matchpairs'
              'nrformats' 'shiftwidth' 'smartindent' 'softtabstop' 'tabstop'
              'textwidth' 'wrapmargin', and in its windows 'conceallevel'
              'foldmethod' 'scrolloff' 'sidescrolloff' 'virtualedit'.
            - The filetype is `neurovim-mission`, so plugins for Markdown
              (rendering, linting, snippets) leave the buffer alone.
              Diagnostics are off.
            - Editor helpers with a buffer switch are switched off:
              completion (vim.b.completion, blink.cmp), mini.nvim's ai,
              clue, completion, jump, jump2d, pairs and surround
              (vim.b.mini*_disable), minuet-ai, copilot.vim.

            Global options stay yours, among them 'ignorecase' and
            'smartcase': a buffer cannot have its own value.
            `:checkhealth neurovim` lists the ones that change Vim keys.

            isolate = false runs missions with your whole setup, as before
            0.1.1 (filetype markdown). The objective and par may then not fit
            what your keys do; `:checkhealth neurovim` names the mappings
            that change Vim keys.

4. GETTING STARTED                                            *neurovim-start*

1. |:NeuroVim| opens NEXUS. Put the cursor on M-01 and press <CR>.
2. Read the briefing, then press <CR> to start the mission.
3. Repair the text. The objective above line 1 says what to change.
4. `:NeuroVim check` scores it. Still wrong: it tells you how many lines.
   Right: a window shows XP, time, keys, tier and what you unlocked.
5. `:NeuroVim reveal` marks the lines that still differ, if you are stuck.

5. COMMANDS                                                *neurovim-commands*

                                                                   *:NeuroVim*
:NeuroVim               NEXUS: level, XP, streak and the missions by chapter,
                        then the KATAs. ✓ solved (with its tier), 🔒 locked
                        (with the level that unlocks it). <CR> opens the
                        mission under the cursor, q closes NEXUS.

:NeuroVim mission {id}  The briefing of mission {id}; Tab completes the ids,
                        upper or lower case. <CR> starts the mission, q closes
                        the briefing. A KATA has no briefing and starts at
                        once. A locked mission names the level that unlocks
                        it and does not open.

:NeuroVim check         Score the current mission buffer: the number of lines
                        still corrupted, or the result in a floating window.
                        It closes when the cursor moves (or with q inside
                        it). One completion per run; `:NeuroVim restart`
                        plays it again.

:NeuroVim result        Show the last result of this session again.

:NeuroVim reveal        Highlight the lines that still differ
                        (|hl-DiffChange|). A missing line is marked on the
                        last line.

:NeuroVim restart       Reload the corrupted text, reset time and keys.

A mission is the buffer neurovim://{id}. The objective stands above line 1,
wrapped to the window; the winbar shows id, time, keys and par. Time and keys
count from the first key typed in the mission buffer. `u` stops at the
corrupted text the mission started with.

                                                              *neurovim-katas*
KATAs are drills: one skill, no story, no briefing. They earn XP like story
missions and unlock with levels like them; KATA-01 is free from the start.

                                                           *neurovim-mappings*
The plugin sets no global keys. These |<Plug>| mappings are yours to map:

  <Plug>(neurovim-nexus)      |:NeuroVim|
  <Plug>(neurovim-check)      :NeuroVim check
  <Plug>(neurovim-reveal)     :NeuroVim reveal
  <Plug>(neurovim-restart)    :NeuroVim restart

Example: >lua
  vim.keymap.set('n', '<leader>nc', '<Plug>(neurovim-check)')
<
Put them under <Leader>, <LocalLeader> or a function key: in a mission
buffer every other key is a plain Vim key (|neurovim-isolate|).
                                                               *neurovim-keys*
What counts as a key: every key you type in the mission buffer, a macro once
for the keys that start it (not for what it replays), and a search or an Ex
command such as :s with all its keys. |:NeuroVim| commands you type do not
count. Mouse clicks and the scroll wheel do not count. A paste from the
terminal costs no key at all, however long: terminals send it as one
bracketed paste. A terminal without bracketed paste sends the pasted
characters as if you had typed them, and then they count. The keys of your
own mapping to a |<Plug>| mapping do count.

6. PROGRESS                                                *neurovim-progress*

XP      Every solved mission earns its XP — also when you solve it again.
Levels  Ten levels, from SIGNAL LOST (0 XP) to SIGNAL ARCHITECT (2500 XP).
        A new level unlocks new missions and KATAs; the result window lists
        them.
Replay  The missions alone do not reach the last levels. When every free
        mission is solved, NEXUS says so: "Replay solved missions for XP —
        level N (X XP) unlocks …". Replaying is how you get past those walls.
Par     Each mission has a par: its authored value, or 20 + 20 × difficulty.
        Gold: at most par keys. Silver: at most 1.5 × par. Bronze: at most
        2.5 × par. More keys: solved, no tier. The result says how many keys
        fewer would reach the next tier.
Bests   Per mission: best time, fewest keys, best keys per minute, runs. A
        run without a single key (pasted, already solved) earns its XP but
        sets no bests.
Streak  Days in a row with at least one solved mission. Days roll over at
        00:00 UTC.

7. SAVE FILE                                                   *neurovim-save*

Progress is saved in stdpath('data')/neurovim/state.json, in the format of
NeuroVim's other builds. Each save re-reads the file first, so two Neovim
instances do not overwrite each other, and writes it atomically. A file that
is not valid save data is moved to state.json.broken-{time} with a warning,
and the game starts fresh — nothing is dropped silently. A file NeuroVim has
no permission to read is left untouched: an error says so, and nothing is
saved until its permissions are fixed.

8. HEALTH                                                    *neurovim-health*

`:checkhealth neurovim` is the first thing to run when something looks wrong.
It reports:

Neovim     the version, and whether it is 0.10 or newer.
Game data  the missions and tables the plugin ships, their schema, and the
           number of missions (54: 40 story, 14 KATA).
Save file  whether state.json is there and readable (no save yet is fine),
           and whether its directory can be written. A broken save, or one
           that cannot be read, is a warning; the check leaves the file
           untouched. NeuroVim moves a broken one aside the next time it
           reads it (any |:NeuroVim|) and leaves an unreadable one alone
           (|neurovim-save|).
Mission buffers
           whether they run in plain Neovim (|neurovim-isolate|). With
           isolate = false, a warning names your mappings that change Vim
           keys. Either way it lists global options that change Vim keys,
           such as 'ignorecase'.
Vendored   which library version and which game-data commit are built in.

The check only reads. It moves, repairs and creates nothing.

9. TROUBLESHOOTING                                  *neurovim-troubleshooting*

Something looks wrong ~
  Run `:checkhealth neurovim` first (|neurovim-health|).

The objective is not visible ~
  It stands above line 1. `gg` brings it back; so does <C-y> at the top.

The result window disappeared ~
  It closes when the cursor moves. `:NeuroVim result` shows it again, until
  you quit Neovim; NEXUS shows your XP, level and tiers.

More keys than I typed ~
  The keys of your own mapping to a |<Plug>| mapping count, and so does a
  paste in a terminal without bracketed paste. See |neurovim-keys|.

A mission is locked ~
  NEXUS names the level that unlocks it. If every free mission is solved,
  replay solved missions for XP (|neurovim-progress|).

My progress is gone ~
  Look for state.json.broken-{time} next to state.json (|neurovim-save|):
  NeuroVim moved a broken file there instead of dropping it.

Progress is not saved ~
  An error names a state.json NeuroVim cannot read: give it back read and
  write permission (`chmod u+rw`); the solved mission can then be checked
  again. `:checkhealth neurovim` shows the file (|neurovim-health|).
